Billing architecture · module dependency audit

Every module, and what it takes to sell it separately

All 69 nav-registered modules, traced for cross-module imports, shared tables, and foreign keys, so pick-your-own-modules billing doesn't sell someone a dead button. Complete inventory first, dependency-safe bundles second, a starting subscription structure last.

Before anything else

Module enablement today is a client-side route guard only — ModuleGate hides the nav item and redirects the route. Nothing in the database or in any library function checks whether a module is paid for. A "Convert to Proposal" button will still insert a real row into proposals even if that module isn't purchased — the row just becomes permanently unreachable until someone buys access to it. Billing enforcement needs to go deeper than reusing this mechanism; the map below tells you where those deeper checks are needed, not what happens today.

04Recommendation

Sell at the bundle level (11 SKUs above), not the individual module level. A true per-module toggle across 67 items will eventually let someone buy Sales without Pre-Sales, or GRN without Purchase Orders — both dead ends today.

  1. Confirm the bundle boundaries above — especially B10 (Recognition & Awards), which is the one bundle that turned out to be independently sellable despite living in the same nav section as Performance Reviews.
  2. Add real enforcement before launch: an org's enabled-bundle set needs to gate at the RLS/RPC layer, not just ModuleGate's route redirect — otherwise a disabled bundle's data can still be written by any button that calls into it directly.
  3. Pick a chain-selling rule: when a bundle with hard upstream requirements is selected (e.g. Sales CRM), either auto-include its requirements in the cart, or block selection with an inline explanation of what's missing.

05Proposed subscription structure

A hybrid that keeps what's already built (billing_plans: Free/Starter/Pro/Enterprise seat tiers, STEP107) and adds true à-la-carte on top, rather than replacing it.

Seat tier — Free / Starter / Pro / Enterprise — still governs how many people can log in, exactly as today. Bundle add-ons — the 11 groups above — govern which modules those people can use, sold as flat monthly/yearly add-ons independent of seat tier. Enterprise keeps its current "all modules included" meaning; every other tier starts with Foundational only and adds bundles à la carte.
